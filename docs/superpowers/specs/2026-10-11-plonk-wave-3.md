# Plonk: third wave (community maps, progress charts, public lobbies)

Date: 2026-10-11. Builds on the multiplayer and wave-2 specs; where they differ, this one wins.

## Why

Neel's goal is to "match worldguessr in functionality". After wave 2 the player-facing gaps against WorldGuessr's own feature documentation are: community maps (browse, play, make), progress charts on the profile, public unranked games for more than two players, and a link from a result to the place on Google Maps. This wave closes them.

Still out, and why: translations (five languages of copy with no translator to check them), native mobile apps, ads and shop, and moderation tooling (reports, bans, a moderator dashboard). A report button on community maps is included so there is a way to flag one; acting on reports is manual.

## Community maps

- A map is a named list of 5 to 500 places made by a signed-in player. Anyone can play it, in singleplayer or as a party map.
- **Making one:** a map editor pane. The maker clicks the world map; the browser snaps the click to the nearest official Google panorama within 500 m (the same lookup the game uses) and adds it to the list, or says there is no coverage there. Places can be removed. A name (3 to 40 characters) and an optional description (up to 200). Save publishes it. The maker can edit or delete their own maps. Limit: 20 maps per account.
- Without a Google key the editor says map making needs Google imagery and is disabled.
- **Playing one:** map id `community:<slug>`. The game loads that map's places from the server instead of a dataset file; scale is the diagonal of its places (minimum 100 km). Community maps are Google-only; on the Panoramax fallback the game says the map cannot be played right now.
- **Browsing:** a Maps pane with three sections: official region and country maps, popular community maps (by plays), and newest. Search by name. A map page shows name, maker (linked to their profile), description, number of places, plays, likes, a small preview map of its places, Play, Like, and Report.
- Starting a game on a community map counts one play (once per account or browser per map per hour).
- No XP and no saved stats beyond the game itself for community maps, as on WorldGuessr.

### API: `api/maps.ts` (new; the ninth function)

`GET /api/maps?list=popular|newest|mine&q=<search>&page=<n>` (no session needed except `mine`):
```ts
{ maps: Array<MapSummary>, page: number, more: boolean }       // 24 per page
MapSummary = { slug: string; name: string; maker: string; places: number; plays: number; likes: number; liked: boolean }
```

`GET /api/maps?slug=<slug>`:
```ts
{ ...MapSummary, description: string, createdAt: string, mine: boolean,
  locations: Array<[id: string, lng: number, lat: number, country: string]> }   // same row shape as the dataset files
```

`POST /api/maps` (session), body `{ action, ... }`:

| action | fields | reply |
|---|---|---|
| `save` | `slug?` (present when editing), `name`, `description`, `locations` (5 to 500 rows) | the map as `GET ?slug=` returns it |
| `delete` | `slug` | `{ deleted: true }` |
| `like` | `slug`, `liked: boolean` | `MapSummary` |
| `play` | `slug` | `{ plays: number }` (no session needed) |
| `report` | `slug`, `reason` (up to 200 characters) | `{ reported: true }` |

Slugs are made by the server from the name plus a short random suffix. Names and descriptions go through the same word mask as chat. Rows are validated (coordinates in range, two-letter country, id up to 64 characters).

`MapId` everywhere now also allows `community:<slug>`.

## Progress charts

- The server keeps a point per day per account: XP total and rating at the end of that day (written when either changes).
- `GET /api/social?profile=<username>` gains `history: Array<{ day: string; xp: number; rating: number }>` (last 90 days).
- Account and profile panes draw two small line charts (XP, rating) from it: plain SVG, no chart library, following the design system.

## Public unranked games

- `unranked` becomes a public game for 2 to 8 players instead of a duel. The queue gathers players: once a second player arrives a 10 second countdown starts, anyone joining the queue in that window is added (up to 8), then the match starts.
- `QueueState` gains `startsAt: string | null` (the end of the countdown, when one is running).
- Scoring, rounds and XP as before.

## Result link

- After a round (singleplayer, daily, streak, and the reveal in a match) the result panel has "Open in Google Maps": a new-tab link to that place's Street View on google.com/maps. Not shown while a round is still being played.
